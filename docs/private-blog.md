# 隐藏空间的维护

四篇文章的原稿仍保存在本机 Journal 文件夹中；网站仓库仅保存加密后的目录、正文，以及用于生成静态页面的哈希地址。隐藏文章不会进入 RSS、站内搜索或 sitemap。

本机的 `.private-blog/sources.json` 记录原稿路径、文章标题、作者和简短介绍，已被 Git 忽略。正文需要修改时直接编辑原稿；标题、署名或简介需要修改时编辑这个配置。日期会自动读取原稿的最后修改日期，按北京时间显示。

修改完成后，在项目目录运行：

```sh
npm run blog:encrypt
```

按提示输入隐藏空间的密码，输入内容不会回显。随后正常构建、发布网站。普通构建无需输入密码，也无需访问本机原稿，因此 GitHub Actions 可以直接使用已经提交的密文。

核对密文中的原稿 SHA-256 指纹、最后修改日期，以及按原稿生成的 HTML 正文：

```sh
npm run blog:check
```

这两个命令也支持通过临时环境变量 `BLOG_PASSWORD` 传入密码；不要将密码或原稿写入已跟踪的文件。默认使用标题生成 SHA-256 地址；如需改标题并保留原有地址，在该文章配置的 `id` 字段中填写原来的 64 位哈希。修改正文不影响地址。

密文只包含显示所需的目录、文章信息与 HTML 正文；原稿以 SHA-256 指纹参与校验，不额外保存重复的 Markdown 副本。

页面使用 PBKDF2-SHA-256（600,000 次迭代）派生 AES-256-GCM 密钥。输入正确密码后仅在当前标签页的会话中记住解密密钥；点击“锁定”会清除密钥及当前页面的已解密内容。中英文页面共用同一份中文原稿。

数字密码可以被离线穷举，哈希地址也不承担访问控制；实际保护来自正文加密和密码强度。
